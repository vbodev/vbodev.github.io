## 1. Schnellstart

### Was PowerShell ist

PowerShell verbindet eine Befehlszeile mit einer Skriptsprache. Befehle geben üblicherweise keine einfachen Texte, sondern .NET-Objekte zurück. Dadurch können Objekte durch die Pipeline weitergereicht und ihre Eigenschaften ohne manuelles Parsen von Zeichenfolgen angesprochen werden.

Vollständige Cmdlet-Namen folgen dem Muster Verb-Noun:

~~~powershell
Get-Process
Get-Service
Set-ExecutionPolicy
Invoke-RestMethod
~~~

Der korrekte Begriff lautet **Cmdlet**. Windows PowerShell 5.1 ist in aktuellen Windows-Versionen integriert; PowerShell 7 ist ein separates plattformübergreifendes Produkt, das bei Bedarf zusätzlich installiert wird.

### Einen PowerShell-Befehl lesen

Diese Zeile lässt sich in folgende Teile zerlegen:

~~~powershell
Get-Process -Name 'powershell' -ErrorAction SilentlyContinue
~~~

- `Get-Process` ist der Cmdlet-Name: Das Verb `Get` bedeutet abrufen, `Process` ist das Substantiv.
- `-Name` ist ein benannter Parameter.
- `'powershell'` ist der Wert des Parameters Name.
- `-ErrorAction` ist ein allgemeiner Parameter, der das Verhalten bei einem nicht terminierenden Fehler steuert.
- `SilentlyContinue` ist der Wert von ErrorAction: Fehler nicht anzeigen und fortfahren. Verwenden Sie dies in echten Skripten nicht ohne Grund.

Syntax und Parametersätze ermitteln:

~~~powershell
Get-Command Get-Process -Syntax
Get-Help Get-Process -Parameter Name
Get-Help about_CommonParameters
~~~

Benannte Parameter sind besser. Eine positionale Schreibweise ist kürzer, aber weniger eindeutig:

~~~powershell
Get-Process -Name 'powershell'  # eindeutig
Get-Process 'powershell'        # funktioniert positional, ist aber weniger explizit
~~~

Ein Switch-Parameter ist ein Schalter ohne separaten Wert:

~~~powershell
Get-ChildItem -Recurse -Force
~~~

Hier aktiviert `-Recurse` die Durchsuchung von Unterordnern, während `-Force` versteckte Elemente anzeigt.

### Wichtige Syntaxzeichen

| Schreibweise | Bedeutung |
|---|---|
| `$name` | Variable |
| `-Name` | Befehlsparameter |
| `'text'` | Zeichenfolge ohne Variablenersetzung |
| `"text $name"` | Zeichenfolge mit Variablenersetzung |
| `$(...)` | Ausdruck innerhalb einer Zeichenfolge oder eines anderen Ausdrucks auswerten |
| `(...)` | Ausdruck gruppieren oder zuerst ein Befehlsergebnis abrufen |
| `{...}` | Codeblock: Rumpf einer Funktion, Schleife, Bedingung oder eines ScriptBlocks |
| `@()` | Immer ein Array erstellen |
| `@{ Key = Value }` | Hashtable mit Schlüssel/Wert-Paaren erstellen |
| `[type]` | Typ angeben oder prüfen |
| `.Property` | Auf eine Objekteigenschaft zugreifen |
| `.Method()` | Eine Methode aufrufen |
| `\|` | Objekte an den nächsten Befehl übergeben |
| `&` | Aufrufoperator: Befehl/Skript ausführen, dessen Pfad ein Ausdruck ist |
| `#` | Einzeiliger Kommentar |
| `<# ... #>` | Mehrzeiliger Kommentar oder kommentarbasierte Hilfe |

Beispiel mit mehreren Konstrukten:

~~~powershell
$serviceName = 'WinRM'
$service = Get-Service -Name $serviceName

if ($service.Status -eq 'Running') {
    "Service $($service.Name) is running"
}
~~~

Der Punkt in `$service.Status` greift auf die Eigenschaft Status zu. `$($service.Name)` wertet innerhalb einer Zeichenfolge mit doppelten Anführungszeichen einen komplexeren Ausdruck als eine einfache Variable aus.

### Variablen und Datentypen

Eine Variable wird durch Zuweisung erstellt:

~~~powershell
$name = 'server01'
$count = 3
$enabled = $true
$checkedAt = Get-Date
~~~

Typen prüfen:

~~~powershell
$name.GetType().FullName
$count.GetType().FullName
$checkedAt.GetType().FullName
~~~

Typen können explizit angegeben werden:

~~~powershell
[string]$computerName = 'server01'
[int]$retryCount = 3
[bool]$enabled = $true
[datetime]$deadline = '2026-08-20'
~~~

Häufige Typen sind `[string]` (Text), `[int]` (Ganzzahl), `[double]` (Dezimalzahl), `[bool]` (boolescher Wert), `[datetime]` (Datum und Uhrzeit), `[array]`/`[object[]]` (geordnete Sammlung), `[hashtable]` (Schlüssel/Wert-Paare) und `[pscustomobject]` (Objekt mit benannten Eigenschaften).

PowerShell konvertiert Typen oft automatisch, verlassen Sie sich aber nicht auf mehrdeutige Konvertierungen:

~~~powershell
'10' + '2'        # '102': Zeichenfolgenverkettung
[int]'10' + 2     # 12: numerische Addition
~~~

### Zeichenfolgen, Arrays, Hashtables und PSCustomObject

Einfache Anführungszeichen bewahren wörtlichen Text. Doppelte Anführungszeichen ersetzen Variablen und Teilausdrücke:

~~~powershell
$name = 'server01'

'Computer: $name'             # Computer: $name
"Computer: $name"             # Computer: server01
"Length: $($name.Length)"     # Length: 8
~~~

Ein Array, einschließlich Bereichsoperator und garantiertem Array-Ausdruck:

~~~powershell
$computers = 'server01', 'server02', 'server03'
$computers[0]
$computers[-1]
$computers.Count
$computers += 'server04'

foreach ($computer in $computers) {
    $computer
}

1..5
5..1

$services = @(Get-Service -Name 'WinRM')
$services.Count
~~~

Eine Hashtable ist für Einstellungen und Befehlsparameter nützlich. Die Übergabe an einen Befehl mit `@settings` heißt **Splatting**: Die Schlüssel werden zu Parameternamen und die Werte zu Argumenten.

~~~powershell
$settings = @{
    ComputerName = 'server01'
    Count        = 1
    Quiet        = $true
}

$settings['ComputerName']
$settings.ComputerName
Test-Connection @settings

$result = [pscustomobject]@{
    ComputerName = 'server01'
    Online       = $true
    CheckedAt    = Get-Date
}

$result.Online
$result | Format-List
$result | Export-Csv .\result.csv -NoTypeInformation
~~~

`$null` bedeutet, dass ein Wert fehlt. Setzen Sie `$null` links von einem Vergleich, damit ein Vergleich mit einer Sammlung eindeutig bleibt:

~~~powershell
$value = $null

if ($null -eq $value) {
    'Value is absent'
}
~~~

### Befehle finden, navigieren und die Objektpipeline verwenden

Aliases sind interaktiv praktisch, in gespeicherten Skripten sollten jedoch vollständige Cmdlet-Namen verwendet werden: `Get-ChildItem` statt `ls`, `Get-Location` statt `pwd`. Das macht Code leichter lesbar und übertragbar.

~~~powershell
Get-Command -Noun Process
Get-Command -Name '*Service*'
Get-Help Get-Process -Examples
Get-Alias
Get-Alias pwd
Get-Alias ls

Get-Location
Get-ChildItem
Set-Location C:\Users
Set-Location ..
Clear-Host
~~~

Die Pipeline übergibt Ergebnisse als Objekte von einem Befehl an den nächsten:

~~~powershell
Get-Process |
    Where-Object CPU -GT 10 |
    Sort-Object CPU -Descending |
    Select-Object -First 10 Name, Id, CPU
~~~

Prüfen Sie Typ und Eigenschaften eines Objekts, bevor Sie es weiterverarbeiten:

~~~powershell
Get-Process | Get-Member
Get-Service | Select-Object -First 5 | Format-Table Name, Status, StartType
~~~

`Format-Table` und `Format-List` dienen der Enddarstellung; setzen Sie sie nicht in die Mitte einer Pipeline, die Objekte noch weiterverarbeiten soll.

`foreach ($item in $items)` ist ein Sprachkonstrukt und verwendet üblicherweise eine bereits im Speicher befindliche Sammlung. `ForEach-Object { ... }` ist ein Pipeline-Cmdlet, das eingehende Objekte bei ihrem Eintreffen verarbeitet. Pipeline-Bindung kann **ByValue** erfolgen, wenn der Objekttyp zu einem Parameter passt, oder **ByPropertyName**, wenn ein Eigenschaftsname zu einem Parameternamen passt.

~~~powershell
Get-Help Stop-Service -Full

[pscustomobject]@{ Name = 'Spooler' } |
    Stop-Service -WhatIf
~~~

Hier wird die Eigenschaft `Name` an den Parameter `-Name` gebunden. Korrekte Eigenschaftsnamen sind daher bei PowerShell-Objekten wichtig.

## 2. Vorhandene Skripte lesen

PowerShell-Skripte haben die Erweiterung `.ps1`. Beim Prüfen fremden Codes ist ein Vorgehen von oben nach unten sinnvoll:

1. Hilfe-Kommentare lesen: `.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER` und `.EXAMPLE`.
2. `param(...)` finden und Eingaben sowie Pflichtparameter verstehen.
3. Variablen auflisten; sie beginnen mit `$`.
4. Funktionen, Schleifen, Bedingungen und Punkte der Remoteausführung finden.
5. Für unbekannte Befehle `Get-Help` und `Get-Command` verwenden.
6. Externe Adressen, Dateien, Module, Berechtigungen und mögliche Nebenwirkungen prüfen.
7. Statische Analyse ausführen und ohne Administratorrechte in einer isolierten Umgebung testen.

Minimal dokumentiertes Skript:

~~~powershell
<#
.SYNOPSIS
Tests availability of hosts from a text file.

.PARAMETER Path
Path to a file containing one name or IP address per line.

.EXAMPLE
.\Test-Hosts.ps1 -Path .\hosts.txt
#>

[CmdletBinding()]
param(
    [Parameter(Mandatory)]
    [ValidateScript({ Test-Path -LiteralPath $_ -PathType Leaf })]
    [string]$Path
)

$computers = Get-Content -LiteralPath $Path

foreach ($computer in $computers) {
    $online = Test-Connection -ComputerName $computer -Count 1 -Quiet

    [pscustomobject]@{
        ComputerName = $computer
        Online       = $online
        CheckedAt    = Get-Date
    }
}
~~~

Verwenden Sie `Write-Verbose` für Diagnosemeldungen in einem Advanced Script/einer Advanced Function; Benutzer aktivieren sie mit `-Verbose`. Geben Sie für Daten Objekte zurück, statt Zeichenfolgen mit `Write-Host` auszugeben.

## 3. Funktionen

Funktionen machen Code wiederverwendbar. Ein minimales Beispiel:

~~~powershell
function Show-PowerShellInfo {
    $PSVersionTable.PSVersion
    Get-Location
}

Show-PowerShellInfo
~~~

Praktische Advanced Function:

~~~powershell
function Test-HostOnline {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory, ValueFromPipeline)]
        [ValidateNotNullOrEmpty()]
        [string[]]$ComputerName
    )

    process {
        foreach ($computer in $ComputerName) {
            [pscustomobject]@{
                ComputerName = $computer
                Online       = Test-Connection -ComputerName $computer -Count 1 -Quiet
            }
        }
    }
}

'server01', 'server02' | Test-HostOnline
~~~

`[CmdletBinding()]` fügt allgemeine Parameter wie `-Verbose`, `-Debug` und `-ErrorAction` hinzu; `param(...)` bildet den Funktionsvertrag; `[string[]]` akzeptiert eine oder mehrere Zeichenfolgen; `ValueFromPipeline` erlaubt Eingaben über `|`; `process` verarbeitet eingehende Pipeline-Elemente; und `[pscustomobject]` gibt strukturierte Ergebnisse zurück.

Eingaben können mit Attributen wie `[ValidateNotNullOrEmpty()]`, `[ValidateRange(1, 10)]` und `[ValidateSet('Info', 'Warning', 'Error')]` geprüft werden. Eine Funktion gibt alle normalen Success-Outputs zurück, nicht nur einen Wert nach `return`. Mit `return` wird die aktuelle Funktion bzw. der Skriptblock beendet. Geben Sie Objekte direkt oder mit `Write-Output` zurück; `Write-Host` ist für UI-Meldungen und `Write-Verbose` für Diagnosen vorgesehen.

Benennen Sie Funktionen nach `ApprovedVerb-Noun` (`Get-Verb` listet bestätigte Verben), deklarieren und typisieren Sie Parameter, geben Sie Objekte statt formatiertem Text zurück und verlangen Sie keine Administratorrechte, wenn sie nicht nötig sind.

### Eine `.ps1` ausführen

~~~powershell
# Aus dem aktuellen Verzeichnis
.\Hello-Friends.ps1

# Vollständiger Pfad; & wird benötigt, wenn der Pfad in einer Zeichenfolge steht
& 'C:\Users\User\Downloads\Hello Friends.ps1'

# Parameter übergeben
& 'C:\Scripts\Test-Hosts.ps1' -Path 'C:\Data\hosts.txt'
~~~

## 4. Execution Policy und sichere Ausführung

Policy nach Scope prüfen:

~~~powershell
Get-ExecutionPolicy -List
~~~

PowerShell-Policies heißen `AllSigned`, `RemoteSigned`, `Restricted`, `Unrestricted`, `Bypass`, `Undefined` und `Default`. Die Scope-Priorität lautet `MachinePolicy`, `UserPolicy`, `Process`, `CurrentUser`, dann `LocalMachine`; Group Policy kann lokale Einstellungen überschreiben.

Auf einem Lerncomputer ist es sicherer, nur die Policy des aktuellen Benutzers zu ändern:

~~~powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
~~~

Für eine vertrauenswürdige heruntergeladene Datei:

~~~powershell
Get-FileHash .\TrustedScript.ps1 -Algorithm SHA256
Unblock-File .\TrustedScript.ps1
~~~

Die Execution Policy schützt vor versehentlicher Ausführung, nicht vor einem entschlossenen Angreifer. Ändern Sie `LocalMachine` nicht, wenn `CurrentUser` oder `Process` ausreicht; verwenden Sie `Bypass` nicht dauerhaft; prüfen Sie Code, Quelle und Hash vor der Ausführung ohne erhöhte Rechte; und nutzen Sie für nicht vertrauenswürdigen Code eine kurzlebige VM oder Windows Sandbox.

## 5. Git und Versionskontrolle

Git speichert die Änderungshistorie; GitHub ist ein Dienst zum Hosten von Git-Repositories und für Zusammenarbeit.

~~~text
working directory → staging area → local commit → remote repository
      git add          git commit         git push
~~~

Das Working Directory enthält bearbeitete Dateien; die Staging Area (Index) enthält Änderungen für den nächsten Commit; ein Commit ist ein gespeicherter Snapshot mit Nachricht; ein Branch ist eine bewegliche Entwicklungslinie; ein Remote ist eine Referenz auf ein entferntes Repository, normalerweise `origin`. Push sendet lokale Commits, Pull holt und integriert Remoteänderungen, Merge verbindet Historien und Rebase setzt lokale Commits auf eine neue Basis und schreibt ihre IDs um.

~~~powershell
git init
git status
git add .
git commit -m "Add initial PowerShell script"

git branch --show-current
git switch -c feature/logging

git remote add origin https://github.com/ORG/REPO.git
git push -u origin feature/logging
git pull --rebase
~~~

Klonen Sie bei einem bestehenden Projekt das Repository, erstellen Sie einen fokussierten Branch, prüfen Sie `git diff`, stagen Sie nur beabsichtigte Dateien, prüfen Sie `git diff --staged` und führen Sie dann Commit und Push aus. Merge-Konflikte müssen bewusst aufgelöst, getestet und erst danach abgeschlossen werden.

~~~powershell
git log --oneline --decorate --graph --all
git diff
git diff --staged
git restore --staged .\file.ps1
~~~

Prüfen Sie vor dem Veröffentlichen, dass Dateien und Historie keine Kennwörter, Token, privaten Schlüssel, internen Adressen oder personenbezogenen Daten enthalten. Geheimnisse gehören nie in Git: Das Löschen aus einem Branch entfernt sie nicht aus der Historie.

## 6. Visual Studio Code

Nützliche PowerShell-Werkzeuge sind die offizielle Microsoft-Erweiterung **PowerShell**, Explorer und globale Suche, die Befehlspalette (`Ctrl+Shift+P`), das integrierte Terminal, Source Control für Git, der Debugger und PSScriptAnalyzer für statische Prüfungen.

Öffnen Sie den Projektordner, erstellen Sie eine `.ps1`, wählen Sie die richtige PowerShell-Sitzung/-Version, führen Sie Auswahl oder Datei im integrierten Terminal aus, prüfen Sie Problems und testen Sie sowohl normale als auch fehlerhafte Eingaben. Ein Breakpoint hält die Ausführung **vor** der markierten Zeile an; verwenden Sie Step Over, Step Into, Step Out und Continue, um Variablen, Watch und Call Stack zu untersuchen.

~~~powershell
Install-Module PSScriptAnalyzer -Scope CurrentUser
Invoke-ScriptAnalyzer -Path .\Script.ps1

Get-PSRepository
Find-Module PSScriptAnalyzer | Select-Object Name, Version, Repository
~~~

Die Installation eines Moduls verändert das System und lädt Code aus der PowerShell Gallery. Prüfen Sie daher zuerst Repository und Herausgeber. Debuggen Sie kein nicht vertrauenswürdiges Skript als Administrator: Auch der Debugger führt dessen Code aus.
