### Informationen über installierte Anwendungen über die Registrierung abrufen

Im Video wird `Get-ItemProperty` verwendet, um Anwendungen aus der Registrierung zu lesen. Dieses funktionierende Beispiel umfasst 64- und 32-Bit-Anwendungen:

```powershell
$uninstallPaths = @(

    'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*'

    Select-Object DisplayName, DisplayVersion, Publisher |
```

## 7. Syntax von PowerShell-Cmdlets

### Grundform

```text
Verb-Noun -Parameter Value
```

Beispiele:

```powershell
Get-Disk
Get-Disk -Number 0
```

Nicht jede angezeigte Eigenschaft ist ein Parameter. Zum Beispiel erscheint `HealthStatus` in der Ausgabe von `Get-Disk`; das bedeutet jedoch nicht, dass ein Parameter `-HealthStatus` vorhanden ist.

Korrekt nach der Eigenschaft filtern:

```powershell
Get-Disk | Where-Object HealthStatus -eq 'Healthy'
```

### Variablen

```powershell
$MyVariable = 'I Love Pizza'
$MyVariable
```

Praktisches Beispiel mit Active Directory:

```powershell
$admin = 'Administrator'
Get-ADUser $admin
```

### Skript aus dem aktuellen Verzeichnis ausführen

```powershell
.\script.ps1
```

Unter Windows ist `.\script.ps1` die übliche und verständlichste Schreibweise.

### Alias `dir`

In PowerShell verweist `dir` auf `Get-ChildItem`:

```powershell
Get-Alias dir
Get-ChildItem
```

Alte CMD-Schalter funktionieren nicht zwingend mit einem Alias. Beispielsweise ist `dir *.txt /s` CMD-Syntax. Das PowerShell-Äquivalent lautet:

```powershell
Get-ChildItem -Path . -Filter '*.txt' -Recurse
```

## 12. Funktionen erstellen

### Funktion zum Prüfen, ob eine Datei existiert

Im Video wird die Funktion `Test-FileExists` gezeigt. Dies ist eine funktionierende rekonstruierte Version:

```powershell
function Test-FileExists {
    param(
        [Parameter(Mandatory)]
        [string]$FilePath
    )

    if (Test-Path -LiteralPath $FilePath -PathType Leaf) {
        "File exists: $FilePath"
    }
    else {
        "File does not exist: $FilePath"
    }
}

Test-FileExists -FilePath 'C:\Data\myfile.txt'
```

Wichtige Elemente:

- `function Name { ... }` — Funktionsdefinition.
- `param(...)` — Funktionsparameter.
- `Test-Path` — prüft einen Pfad.
- `-LiteralPath` — behandelt den Pfad wörtlich.
- `-PathType Leaf` — erwartet eine Datei, kein Verzeichnis.

### Funktion für AD-Benutzerinformationen

Im Video wird `Get-UserInfo` mit Copilot erstellt. Dies ist eine funktionierende Version:

```powershell
function Get-UserInfo {
    param(
        [Parameter(Mandatory)]
        [string]$Identity
    )

    Get-ADUser -Identity $Identity -Properties Department |
        Select-Object Name, SamAccountName, Department, Enabled
}

Get-UserInfo -Identity 'Administrator'
```

Direkt in die Konsole eingegebene Funktionen existieren nur bis zum Ende der Sitzung. Speichern Sie sie für die Wiederverwendung in einer `.ps1`-Datei, einem Modul oder Profil.

## 14. Execution Policies verwalten

### Aktuelle Policies prüfen

```powershell
Get-ExecutionPolicy
Get-ExecutionPolicy -List
```

### Im Kurs gezeigter Befehl

```powershell
Set-ExecutionPolicy -ExecutionPolicy Unrestricted
```

Standardmäßig wird der Scope `LocalMachine` verwendet; daher sind Administratorrechte erforderlich.

### Eine sicherere übliche Variante

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Für eine Umgebung, in der alle Skripte signiert werden:

```powershell
Set-ExecutionPolicy -ExecutionPolicy AllSigned -Scope LocalMachine
```

Eine einzelne geprüfte heruntergeladene Datei entsperren, ohne die allgemeine Policy zu lockern:

```powershell
Unblock-File -Path '.\script.ps1'
```

### Hilfe abrufen

```powershell
Get-Help Set-ExecutionPolicy -Full
```

### Policy remote prüfen und ändern

```powershell
Invoke-Command -ComputerName 'DC02' -ScriptBlock {
    Get-ExecutionPolicy -List
}
```

Wenn die Änderung tatsächlich erforderlich ist:

```powershell
Invoke-Command -ComputerName 'DC02' -ScriptBlock {
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope LocalMachine -Force
    Get-ExecutionPolicy -List
}
```

> Eine Execution Policy schützt vor dem versehentlichen Ausführen ungeeigneter Skripte, ist aber keine vollständige Sicherheitsgrenze. Group Policy hat Vorrang vor lokalen Scopes.

## 21. PowerShell-Cmdlets protokollieren

### Arten der Protokollierung aus der Lektion

- **Script Block Logging** — Inhalte von Befehlen, Funktionen und Skriptblöcken.
- **Module Logging** — Ausführung von Befehlen ausgewählter Module.
- **Transcription** — Eingabe und Konsolenausgabe einer Sitzung.
- **Engine Logging** — interne PowerShell-Ereignisse beim Start und Beenden.
- **Protected Event Logging** — CMS-Verschlüsselung für sensible Ereignisinhalte.

### Script Block Logging für PowerShell 7 — Skript aus dem Video

```powershell
function Enable-PSScriptBlockLogging {
    $basePath = @(
        'HKLM:\Software\Policies\Microsoft'
        'PowerShellCore\ScriptBlockLogging'
    ) -join '\'

    if (-not (Test-Path $basePath)) {
        $null = New-Item $basePath -Force
    }

    Set-ItemProperty $basePath `
        -Name EnableScriptBlockLogging `
        -Value '1'
}

Enable-PSScriptBlockLogging
```

### Windows PowerShell 5.1 — anderer Registrierungspfad

```powershell
$basePath = 'HKLM:\Software\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging'

if (-not (Test-Path $basePath)) {
    $null = New-Item -Path $basePath -Force
}

Set-ItemProperty -Path $basePath `
    -Name EnableScriptBlockLogging `
    -Type DWord `
    -Value 1
```

In einer Domäne sollte diese Einstellung nach Möglichkeit zentral über Group Policy aktiviert werden.

### Script-Block-Logging-Ereignisse lesen

Windows PowerShell 5.1:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-PowerShell/Operational'
    Id      = 4104
} -MaxEvents 100 |
    Select-Object TimeCreated, Id, UserId, Message
```

PowerShell 7:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'PowerShellCore/Operational'
    Id      = 4104
} -MaxEvents 100 |
    Select-Object TimeCreated, Id, UserId, Message
```

### Sitzung manuell mitschreiben

```powershell
$directory = 'C:\ProgramData\PowerShell\Transcripts'
New-Item -ItemType Directory -Path $directory -Force | Out-Null

Start-Transcript `
    -OutputDirectory $directory `
    -IncludeInvocationHeader

# Administrative Befehle

Stop-Transcript
```

Transkripte und Script Block Logging können sensible Werte aufzeichnen. Beschränken Sie ACLs, konfigurieren Sie zentrale Sammlung, Protokollgröße und Aufbewahrung und verwenden Sie bei Bedarf Protected Event Logging.

## 22. Cmdlets des Common Information Model (CIM)

Die wichtigsten in der Lektion aufgeführten Cmdlets:

```powershell
Get-CimInstance
New-CimInstance
Remove-CimInstance
Set-CimInstance
Get-CimClass
Invoke-CimMethod

New-CimSession
Get-CimSession
Remove-CimSession
New-CimSessionOption
```

| Cmdlet | Zweck |
|---|---|
| `Get-CimInstance` | Ruft Instanzen einer CIM-Klasse ab |
| `New-CimInstance` | Erstellt eine Instanz |
| `Remove-CimInstance` | Entfernt eine Instanz |
| `Set-CimInstance` | Ändert eine Instanz |
| `Get-CimClass` | Ruft Klassendefinitionen ab |
| `Invoke-CimMethod` | Ruft eine CIM-Klassenmethode auf |
| `New-CimSession` | Erstellt eine lokale oder Remote-CIM-Sitzung |
| `Get-CimSession` | Zeigt aktive CIM-Sitzungen |
| `Remove-CimSession` | Schließt eine CIM-Sitzung |
| `New-CimSessionOption` | Erstellt einen Satz von Sitzungsoptionen |

## 23. CIM-Demonstration

### Informationen über lokale Datenträger

```powershell
Get-CimInstance -ClassName Win32_DiskDrive |
    Select-Object Model, Size, Status
```

Praktischere Darstellung der Größe:

```powershell
Get-CimInstance -ClassName Win32_DiskDrive |
    Select-Object Model,
        @{Name = 'SizeGB'; Expression = { [math]::Round($_.Size / 1GB, 2) }},
        Status
```

### Remote-CIM-Sitzung erstellen

```powershell
$session = New-CimSession -ComputerName 'PS-SERVER01'
```

### Gesamten physischen Arbeitsspeicher ermitteln

```powershell
$memory = Get-CimInstance `
    -CimSession $session `
    -ClassName Win32_PhysicalMemory |
    Measure-Object -Property Capacity -Sum

[pscustomobject]@{
    ComputerName = 'PS-SERVER01'
    MemoryGB     = [math]::Round($memory.Sum / 1GB, 3)
}
```

### Sitzung schließen

```powershell
Remove-CimSession -CimSession $session
```

## B. Mehrere Server über CIM inventarisieren

```powershell
[CmdletBinding()]
param(
    [Parameter(Mandatory)]
    [string[]]$ComputerName
)

$sessions = New-CimSession -ComputerName $ComputerName

try {
    foreach ($session in $sessions) {
        $os = Get-CimInstance `
            -CimSession $session `
            -ClassName Win32_OperatingSystem

        $memory = Get-CimInstance `
            -CimSession $session `
            -ClassName Win32_PhysicalMemory |
            Measure-Object Capacity -Sum

        [pscustomobject]@{
            ComputerName = $session.ComputerName
            OS           = $os.Caption
            Version      = $os.Version
            MemoryGB     = [math]::Round($memory.Sum / 1GB, 2)
            LastBoot     = $os.LastBootUpTime
        }
    }
}
finally {
    $sessions | Remove-CimSession
}
```

# Wichtige Hinweise für die Produktionsumgebung

## 1. `Unrestricted` ist nur ein Lernbeispiel

Der Kurs demonstriert `Set-ExecutionPolicy Unrestricted` und fügt den Befehl sogar dem Profil hinzu. Diese Einstellung ist für eine Produktionsumgebung zu weitreichend. Normalerweise werden `RemoteSigned` oder `AllSigned` verwendet oder die Policy wird über Group Policy verwaltet. Für eine einzelne geprüfte Datei kann `Unblock-File` verwendet werden.

## 2. `Get-WmiObject Win32_Product` ist nicht empfehlenswert

Der Befehl aus dem Kurs kann langsam sein und Konsistenzprüfungen oder Reparaturen von MSI-Paketen auslösen. Für die Inventarisierung sollten die Uninstall-Schlüssel der Registry gelesen oder ein Unternehmens-Inventarisierungstool verwendet werden.

## 3. `Get-EventLog` dient der Kompatibilität, `Get-WinEvent` ist die moderne Variante

`Get-EventLog` funktioniert nur mit klassischen Logs und wird aus Gründen der Abwärtskompatibilität beibehalten. `Get-WinEvent` unterstützt moderne Windows-Event-Log-/ETW-Protokolle und effiziente Filter über `-FilterHashtable`.

## 4. PowerShell 7 und Windows PowerShell 5.1 sind unterschiedliche Produkte

Sie laufen parallel. Nicht jedes ältere Windows-Modul ist gleichermaßen mit PowerShell 7 kompatibel. Prüfen Sie `$PSVersionTable`, `Get-Module -ListAvailable` und die Kompatibilität des jeweiligen Moduls.

## 5. Protokolle nicht grundlos leeren

`Clear-EventLog` zerstört die aktuellen Ereignisse im ausgewählten klassischen Log. Exportieren Sie das Protokoll vor dem Leeren, wenn es für Audit, Diagnose oder Untersuchung benötigt werden könnte.

## 6. Protokollierung kann Geheimnisse aufzeichnen

Script Block Logging und Transcription können Token, Kennwörter, Connection Strings und andere sensible Daten erfassen, wenn sie in der Befehlszeile oder Ausgabe erscheinen. Schützen Sie ACLs, zentrale Sammlung und die Schlüssel von Protected Event Logging.
