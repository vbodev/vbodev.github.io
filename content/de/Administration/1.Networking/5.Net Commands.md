## 1. `ping` (Packet Internet Groper)

**Wesen:** Das ist ein «Sonar» für Netzwerke. Verwendet das Protokoll **ICMP** (Internet Control Message Protocol). Der Computer sendet einen «Echo-Request» und wartet auf eine «Echo-Reply».

**Was er uns genau sagt:**
1. **Erreichbarkeit (Availability):** Ist der entfernte Knoten erreichbar.
2. **Paketverluste (Packet Loss):** Wenn 4 Pakete gesendet wurden, aber nur 3 zurückgekommen sind (25% loss), ist die Leitung gestört, überlastet oder das Gerät hat einen Fehler. Bei VoIP oder Spielen ist das kritisch.
3. **Antwortzeit (Latency/RTT):** Wie viele Millisekunden das Signal hin und zurück geflogen ist.
    - < 1 ms: Gerät im lokalen Netzwerk.
    - 10-50 ms: Gutes Internet (innerhalb des Landes/der Region).
    - > 150 ms: Ein anderer Kontinent oder Satellitenkanal.
**Nützliche Optionen (CMD):**
- `ping -t` — **Endloser Ping.** Unverzichtbar beim Konfigurieren von Antennen oder beim Umstecken von Kabeln.
- `ping -l 1000` — **Paketgröße.** Standardmäßig sind Pakete klein (32 Bytes). Der Schalter `-l` (length) ermöglicht das Senden eines «schweren» Pakets (z.B. 1000 oder 1500 Bytes), um zu prüfen, ob das Netzwerk die Last aushält (MTU).
- `ping -a` — Versucht, den Computernamen anhand der IP-Adresse zu ermitteln.

## 2. `tracert` (Trace Route)

**Wesen:** Zeigt die Routenkarte.
**Wie es funktioniert (TTL-Magie):** Jedes IP-Paket hat ein Feld **TTL (Time To Live)** — «Lebenszeit». Das ist ein Sprungzähler.
1. Der Befehl sendet ein Paket mit TTL=1. Es kommt beim ersten Router an, TTL wird 0, der Router zerstört das Paket und sendet die Nachricht «Time exceeded». So erfahren wir die IP des ersten Routers.
2. Ein Paket mit TTL=2 wird gesendet. Es passiert den ersten Router, stirbt am zweiten. Wir erfahren die IP des zweiten.
3. Und so weiter, bis das Ziel erreicht ist.

**Diagnose-Feinheiten:**
- **Wo bremst das Internet?** Wenn in den ersten Schritten (innerhalb des Provider-Netzwerks) die Antwortzeit klein ist (1-5 ms), aber beim Übergang zum Backbone-Provider auf 200 ms ansteigt — dann liegt das Problem nicht an deinem Router, sondern an globalen Kanälen.
- **Schalter `-d`:** `tracert -d ya.ru`. Die nützlichste Option! Sie verbietet dem Befehl, IP-Adressen in Knotennamen umzuwandeln. Das beschleunigt die Ablaufverfolgung erheblich.

## 3. `ipconfig` (Internet Protocol Configuration)

**Wesen:** Der Ausweis deines Netzwerkadapters.
**Detaillierte Erklärung der Parameter:**
- **Subnet Mask (Subnetzmaske):** Bestimmt die Grenzen deines lokalen Netzwerks. Normalerweise `255.255.255.0`.
- **Default Gateway (Standardgateway):** Das ist die IP-Adresse deines Routers. Hierhin sendet der Computer alle Pakete, die für das Internet bestimmt sind. Wenn kein Ping zum Gateway geht — liegt das Problem in deinem WLAN oder dem Kabel zum Router.
**Wiederbelebungsbefehle (wenn das Netzwerk «eingefroren» ist oder keine IP zugewiesen wurde):**
1. `ipconfig /release` — Aktuelle IP-Adresse freigeben.
2. `ipconfig /renew` — Neue IP-Adresse vom DHCP-Server (Router) anfordern.
3. `ipconfig /flushdns` — **DNS-Cache leeren.** Sehr wichtig! Wenn eine Website auf einen neuen Server umgezogen ist, aber dein Computer die alte Adresse gespeichert hat, zwingt dieser Befehl ihn, das Alte zu «vergessen» und erneut nachzufragen.

## 4. `nslookup` (Name Server Lookup)

**Wesen:** Direkte Kommunikation mit dem DNS-Server. Das ist ein Tool zum Gespräch mit dem Telefonbuch des Internets.
**Betriebsmodi:**
1. **Einfach:** `nslookup google.com` — verwendet deinen Standard-DNS.
2. **Alternative prüfen:** `nslookup google.com 1.1.1.1` — fragt die Adresse beim Cloudflare-Server (1.1.1.1) ab, ignoriert die Einstellungen deines Providers. Wenn das funktioniert, aber ohne `1.1.1.1` nicht — ist der DNS deines Providers kaputt.
**Fortgeschrittenes Niveau (Eintragstypen):**
- Starte einfach `nslookup` (Enter drücken).
- Gib innen `set type=mx` ein.
- Gib `gmail.com` ein.
- Du siehst Googles Mailserver. Das ist nötig, um zu verstehen, wohin E-Mails der Domain gehen.

## 5. `netstat` (Network Statistics)

**Wesen:** Röntgenaufnahme aktiver Verbindungen. Zeigt, wer wohin und über welchen Port verbunden ist.
**Wichtige Zustände (State):**
- **ESTABLISHED:** Stabile Verbindung, Datenübertragung läuft.
- **LISTENING:** Ein Programm hat einen Port geöffnet und wartet auf Gäste. Das ist eine potenzielle Sicherheitslücke.
- **TIME_WAIT:** Verbindung geschlossen, aber das System wartet, um sicherzustellen, dass alle Pakete angekommen sind.
**Beste Schlüsselkombination:** `netstat -ano`
- `-a`: Alle Ports.
- `-n`: Numerische Ansicht (zeigt IP statt Namen, arbeitet schneller).
- `-o`: Fügt die Spalte **PID (Process ID)** hinzu.
**Wie man einen Virus/Spion erwischt:**
1. `netstat -ano` eingeben.
2. Eine seltsame Verbindung mit einer fremden IP sehen.
3. Ihre PID ansehen (z.B. 4520).
4. Task-Manager öffnen → Details → PID 4520 suchen.
5. Den Prozessnamen sehen, der das tut.

## Alle Befehle

|**Befehl**|**Parameter (Optionen)**|**Verwendungsbeispiel**|**Wofür (Situation)**|
|---|---|---|---|
|**PING**|`-t`|`ping google.com -t`|**Endloser Ping.** Unverzichtbar beim Umstecken von Kabeln oder Neustart des Routers. (Stopp: `Ctrl+C`)|
||`-l` (Größe)|`ping ya.ru -l 1400`|**Stabilitätsprüfung.** Sendet ein schweres Paket (1400 Bytes). Wenn normaler Ping geht, aber dieser verloren geht — Problem mit Leitungsqualität oder MTU-Einstellungen.|
|**IPCONFIG**|`/all`|`ipconfig /all`|**Vollständige Dossier.** Zeigt MAC-Adresse und DNS-Server (normales `ipconfig` versteckt das).|
||`/flushdns`|`ipconfig /flushdns`|**«Pille» gegen Fehler.** Leert DNS-Cache. Wenn eine Website die IP geändert hat, aber bei dir eine alte Version oder Fehler erscheint — eingeben.|
||`/renew`|`ipconfig /renew`|**IP-Anfrage.** Erzwingt beim Router, eine neue Adresse auszugeben. Hilft bei IP-Adresskonflikten.|
|**TRACERT**|`-d`|`tracert -d 8.8.8.8`|**Schnelle Ablaufverfolgung.** Verschwendet keine Zeit damit, Knotennamen herauszufinden, zeigt nur IPs. Arbeitet 3-5x schneller.|
|**NETSTAT**|`-ano`|`netstat -ano`|**Vollständiger Scan.** `-a`: alle Ports, `-n`: als Zahlen (schnell), `-o`: zeigt **PID** des Prozesses. Die PID im Task-Manager führt zum Programm.|
||`-ab`|`netstat -ab`|**Schuldigen finden.** Zeigt den **Namen** des Programms (exe), das den Port geöffnet hat. _Erfordert Ausführung der Eingabeaufforderung als Administrator._|
|**NSLOOKUP**|(IP des Servers)|`nslookup ya.ru 8.8.8.8`|**Prüfung «von außen».** Fragt die IP der Website nicht beim Provider, sondern speziell beim Google-Server (8.8.8.8) ab. Hilft zu verstehen, wer schuld ist: der Provider oder die Website.|
