## 1. Primitive und Referenztypen

#### **Primitive Typen (Primitive Types)**
Dies sind die grundlegenden Datentypen, die den **Wert direkt** speichern und nicht einen Verweis auf ein Objekt.
Java hat **8 primitive Typen**:

| Kategorie  | Typ  | Größe  | Bereich  | Beispielwert  |
| ------------ | --------- | ------------------------- | ------------------- | --------------------- |
| Ganzzahlen  | `byte`  | 1 Byte  | -128 … 127  | `byte b = 10;`  |
|  | `short`  | 2 Byte  | -32 768 … 32 767  | `short s = 500;`  |
|  | `int`  | 4 Byte  | ≈ ±2 Milliarden  | `int i = 1000;`  |
|  | `long`  | 8 Byte  | ±9 Quintillionen  | `long l = 100000L;`  |
| Gleitkommazahlen | `float`  | 4 Byte  | ~7 Stellen Genauigkeit | `float f = 1.23f;`  |
|  | `double`  | 8 Byte  | ~15 Stellen Genauigkeit | `double d = 1.23456;` |
| Zeichen  | `char`  | 2 Byte  | Unicode Zeichen  | `char c = 'A';`  |
| Boolesche | `boolean` | 1 Bit (im Speicher – 1 Byte) | `true` / `false`  | `boolean b = true;`  |
💡 **Besonderheiten:**
- Primitive Typen können nicht `null` sein.
- Standardmäßig werden sie mit Null (0, 0.0, `false`, `'\u0000'`) initialisiert, wenn es Felder einer Klasse sind.
- In lokalen Variablen muss **zwingend** ein Wert explizit zugewiesen werden – andernfalls tritt ein Kompilierungsfehler auf.

#### **Referenztypen (Reference Types)**

Referenztypen **speichern keinen Wert**, sondern **enthalten eine Adresse** des Objekts im Speicher (im Heap).

Beispiele:
```java
String s = "Hello";
int[] numbers = {1, 2, 3};
Person p = new Person("Alex");
```

Hier:
- `s` speichert einen Verweis auf das Objekt `String` im Heap.
- `numbers` ist ein Verweis auf ein Array.
- `p` ist ein Verweis auf das Objekt `Person`.
💡 **Alle Klassen, Arrays und Interfaces** sind Referenztypen.
Selbst `String` ist kein primitiver Typ, obwohl er sich wie einer verhält, aufgrund der _Immutability_ (Unveränderlichkeit).

## 2. Autoboxing und Unboxing

Um Primitive als Objekte zu verwenden, bietet Java **Wrapper-Klassen**:

| Primitiv  | Wrapper-Klasse |
| --------- | ------------- |
| `int`  | `Integer`  |
| `double`  | `Double`  |
| `boolean` | `Boolean`  |
| `char`  | `Character`  |
| `long`  | `Long`  |
| `float`  | `Float`  |
| `short`  | `Short`  |
| `byte`  | `Byte`  |

**Autoboxing** ist die automatische Umwandlung eines Primitivtyps in ein Objekt:
```java
Integer num = 5; // automatische Umwandlung int → Integer
```

**Unboxing** ist die umgekehrte Umwandlung:
```java
int x = num; // automatische Entnahme von Integer → int
```

💡 **Wichtige Hinweise:**
```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b); // true (IntegerCache von -128 bis 127)

Integer c = 128;
Integer d = 128;
System.out.println(c == d); // false (es wurden verschiedene Objekte erstellt)
```
→ Vergleichen Sie Wrapper mit `.equals()` und nicht mit `==`.

## 3. Speicher: Stack vs Heap

#### **Stack (Stapel)**
- Speichert **Methodenaufrufe und lokale Variablen**.
- Jeder Thread hat **seinen eigenen Stack**.
- Daten gehen beim Verlassen der Methode verloren.

Beispiel:
```java
void example() {
  int x = 10;  // wird auf dem Stack gespeichert
  String s = "Hello";  // Verweis wird auf dem Stack gespeichert, Objekt im Heap
}
```

#### **Heap (Haufen)**
- Speichert **Objekte** (alle Instanzen von Klassen, Arrays, Strings).
- Gemeinsam für alle Threads.
- Wird vom **Garbage Collector (GC)** verwaltet.

Beispiel:
```java
Person p = new Person("Alex"); // Objekt im Heap, Verweis auf dem Stack
```

## 4. Lebenszyklus von Objekten

1. **Erstellung**: `new` weist Speicher im Heap zu.
2. **Verwendung**: Das Objekt lebt, solange es mindestens ein Verweis darauf gibt.
3. **Garbage Collection**: Wenn kein Verweis mehr auf das Objekt existiert, bereinigt der GC es.

Der GC wird nicht manuell aufgerufen, aber man kann **bitten**:
```java
System.gc(); // nur eine Empfehlung, keine Garantie
```

## 5. Parameterübergabe in Methoden

Java **übergibt Argumente immer nach Wert** (by value).
Wenn es sich um einen Referenztyp handelt, wird der **Verweis selbst kopiert**, nicht das Objekt.

```java
void modify(Person p) {
  p.name = "Changed"; // ändert das ursprüngliche Objekt
}
```

📍 Das bedeutet:
- Bei Primitiven wird der Wert kopiert, das Original bleibt unverändert;
- Bei Objekten wird der Verweis kopiert, und man kann die internen Felder ändern.

### 6. Wichtige Konzepte des JVM-Speichers

| Speicherbereich | Zweck |
|---|---|
| **Stack** | Lokale Variablen und Methodenaufrufe |
| **Heap** | Alle Objekte, die vom GC verwaltet werden |
| **Metaspace (bis Java 8 – PermGen)** | Speichert Metadaten der Klassen und Bytecode |
| **PC Register** | Speichert die aktuelle Instruktion des Threads |
| **Native Method Stack** | Stack von Aufrufen nativen (nicht Java) Methoden |

## 7. Best Practices

- ✅ Verwende Primitive anstelle von Wrapper, wenn `null` nicht erforderlich ist.
- ✅ Missbrauche kein Autoboxing innerhalb von Schleifen – es werden unnötige Objekte erstellt.
- ✅ Verwende `.equals()` zum Vergleichen von Wrappern.
- ✅ Denke daran, dass `String` immutable ist (erstellt neue Objekte bei Änderungen).
- ✅ Optimiere den Speicher mit `StringBuilder`, wenn du innerhalb einer Schleife konkatenierst.
