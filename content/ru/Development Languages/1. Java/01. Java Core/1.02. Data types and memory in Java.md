## 1.  Примитивные и ссылочные типы

#### **Примитивные типы (Primitive Types)**

Это базовые типы данных, которые хранят **значение напрямую**, а не ссылку на объект.  
Java имеет **8 примитивных типов**:

| Категория    | Тип       | Размер                    | Диапазон            | Пример значения       |
| ------------ | --------- | ------------------------- | ------------------- | --------------------- |
| Целые числа  | `byte`    | 1 байт                    | -128 … 127          | `byte b = 10;`        |
|              | `short`   | 2 байта                   | -32 768 … 32 767    | `short s = 500;`      |
|              | `int`     | 4 байта                   | ≈ ±2 млрд           | `int i = 1000;`       |
|              | `long`    | 8 байт                    | ±9 квинтиллионов    | `long l = 100000L;`   |
| Вещественные | `float`   | 4 байта                   | ~7 знаков точности  | `float f = 1.23f;`    |
|              | `double`  | 8 байт                    | ~15 знаков точности | `double d = 1.23456;` |
| Символ       | `char`    | 2 байта                   | Unicode символы     | `char c = 'A';`       |
| Логический   | `boolean` | 1 бит (в памяти — 1 байт) | `true` / `false`    | `boolean b = true;`   |
💡 **Особенности:**

- Примитивы не могут быть `null`.
- По умолчанию инициализируются нулями (0, 0.0, `false`, `'\u0000'`) если это поля класса.
- В локальных переменных **обязательно** нужно явно присвоить значение — иначе будет ошибка компиляции.
#### **Ссылочные типы (Reference Types)**

Ссылочные типы **не хранят значение**, а **содержат адрес** объекта в памяти (в heap).

Примеры:
```java
String s = "Hello";
int[] numbers = {1, 2, 3};
Person p = new Person("Alex");
```

Здесь:
- `s` хранит ссылку на объект `String` в heap.
- `numbers` — ссылка на массив.
- `p` — ссылка на объект `Person`.
💡 **Все классы, массивы и интерфейсы** — это ссылочные типы.  
Даже `String` — не примитив, хотя ведёт себя как таковой из-за _immutability_ (неизменяемости).
## 2. Автоупаковка и распаковка (Autoboxing / Unboxing)

Чтобы использовать примитивы как объекты, Java предоставляет **обёртки (Wrapper Classes)**:

| Примитив  | Класс-обёртка |
| --------- | ------------- |
| `int`     | `Integer`     |
| `double`  | `Double`      |
| `boolean` | `Boolean`     |
| `char`    | `Character`   |
| `long`    | `Long`        |
| `float`   | `Float`       |
| `short`   | `Short`       |
| `byte`    | `Byte`        |
**Autoboxing** — автоматическое преобразование примитива в объект:
```java
Integer num = 5; // автопреобразование int → Integer
```

**Unboxing** — обратное преобразование:
```java
int x = num; // автоматическое извлечение Integer → int
```

💡 **Подводные камни:**
```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b); // true (кеш IntegerCache от -128 до 127)

Integer c = 128;
Integer d = 128;
System.out.println(c == d); // false (созданы разные объекты)
```
→ сравнивать обёртки нужно через `.equals()`, не `==`.
## 3. Память: Stack vs Heap

#### **Stack (стек)**
- Хранит **вызовы методов и локальные переменные**.
- Каждая нить (thread) имеет **свой стек**.
- Данные исчезают при выходе из метода.

Пример:
```java
void example() {
    int x = 10;           // хранится в стеке
    String s = "Hello";   // ссылка хранится в стеке, объект в heap
}
```
#### **Heap (куча)**
- Хранит **объекты** (все экземпляры классов, массивы, строки).
- Общая для всех потоков.
- Управляется **Garbage Collector’ом** (GC).

Пример:
```java
Person p = new Person("Alex"); // объект в heap, ссылка в stack
```
## 4. Жизненный цикл объектов

1. **Создание**: `new` — выделяет память в heap.
2. **Использование**: объект живёт, пока есть хотя бы одна ссылка на него.
3. **Сборка мусора**: когда на объект нет ссылок — GC его очищает.

GC не вызывается вручную, но можно **попросить**:
```java
System.gc(); // только рекомендация, не гарантия
```
## 5. Передача параметров в методы

Java **всегда передаёт аргументы по значению** (by value).  
Но если это ссылочный тип — копируется **сама ссылка**, а не объект.

```java
void modify(Person p) {
    p.name = "Changed"; // изменится в оригинальном объекте
}
```
📍 Значит:
- для примитивов — значение копируется, оригинал не меняется;
- для объектов — копируется ссылка, и можно изменить внутренние поля.
### 6. Ключевые понятия памяти JVM

| Область памяти                      | Назначение                              |
| ----------------------------------- | --------------------------------------- |
| **Stack**                           | локальные переменные и вызовы методов   |
| **Heap**                            | все объекты, управляемые GC             |
| **Metaspace (до Java 8 — PermGen)** | хранит метаданные классов и bytecode    |
| **PC Register**                     | хранит текущую инструкцию потока        |
| **Native Method Stack**             | стек вызовов нативных (не Java) методов |
## 7. Best Practices

- ✅ Используй примитивы вместо обёрток, если не требуется `null`.  
- ✅ Не злоупотребляй autoboxing внутри циклов — создаются лишние объекты.  
- ✅ Для сравнения обёрток всегда применяй `.equals()`.  
- ✅ Помни, что `String` — immutable (создаёт новые объекты при изменении).  
- ✅ Оптимизируй память через `StringBuilder`, если выполняешь конкатенацию в цикле.
