- `-Force` — принудительное выполнение там, где cmdlet поддерживает этот параметр.
- `Tab` — автодополнение команды, параметра, пути или допустимого значения.

## 4. Upgrading Windows PowerShell

### Проверить версию

```powershell

```

Наиболее полезные поля:

```powershell

$PSVersionTable.PSEdition
```

### Найти и установить PowerShell 7 через WinGet

**Из курса:**

```powershell
winget search Microsoft.PowerShell
winget install Microsoft.PowerShell
```

Более однозначная форма с точным ID пакета:

```powershell
winget search --id Microsoft.PowerShell
winget install --id Microsoft.PowerShell --source winget
```

PowerShell 7 устанавливается рядом с Windows PowerShell 5.1, а не заменяет его. Исполняемый файл PowerShell 7 — `pwsh.exe`; Windows PowerShell 5.1 — `powershell.exe`.

```powershell

```

PowerShell-вариант без команды `more`:

```powershell

```

> Для Windows Server Microsoft называет MSI предпочтительным вариантом корпоративного развёртывания. WinGet включён в Windows Server 2025 с Desktop Experience, но отсутствует штатно в Windows Server 2022 и более ранних версиях.

## 5. Managing Windows Servers using Windows Admin Center and PowerShell

### Проверить диски

В транскрипте встречается распознанное `Get-Disc`; правильный cmdlet:

```powershell

```

### Получить сведения об установленных приложениях через реестр

В видео используется `Get-ItemProperty` для чтения приложений из реестра. Рабочий пример, охватывающий 64- и 32-разрядные приложения:

```powershell
$uninstallPaths = @(
    'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*'
    'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*'
)

Get-ItemProperty -Path $uninstallPaths |
    Where-Object DisplayName |
    Select-Object DisplayName, DisplayVersion, Publisher |
    Sort-Object DisplayName
```

Windows Admin Center может открыть PowerShell на выбранном сервере, фактически предоставляя удалённую административную сессию.

## 7. PowerShell cmdlet syntax

### Базовая форма

```text
Verb-Noun -Parameter Value
```

Примеры:

```powershell
Get-Disk
Get-Disk -Number 0
```

Не каждое отображаемое свойство является параметром. Например, `HealthStatus` есть в выводе `Get-Disk`, но это не означает, что существует параметр `-HealthStatus`.

Правильная фильтрация свойства:

```powershell
Get-Disk | Where-Object HealthStatus -eq 'Healthy'
```

### Переменные

```powershell
$MyVariable = 'I Love Pizza'
$MyVariable
```

Практический пример с Active Directory:

```powershell
$admin = 'Administrator'
Get-ADUser $admin
```

### Запуск сценария из текущего каталога

```powershell
.\script.ps1
```

В Windows стандартная и наиболее понятная запись — `.\script.ps1`.

### Alias `dir`

В PowerShell `dir` указывает на `Get-ChildItem`:

```powershell
Get-Alias dir
Get-ChildItem
```

Старые ключи CMD не обязаны работать с alias. Например, `dir *.txt /s` — синтаксис CMD. PowerShell-эквивалент:

```powershell
Get-ChildItem -Path . -Filter '*.txt' -Recurse
```

## 12. Creating functions

### Функция проверки существования файла

В видео показана функция `Test-FileExists`. Рабочая восстановленная версия:

```powershell
function Test-FileExists {
    param(
        [Parameter(Mandatory)]
        [string]$FilePath
    )

    if (Test-Path -LiteralPath $FilePath -PathType Leaf) {
        "File exists: $FilePath"
    }
    else {
        "File does not exist: $FilePath"
    }
}

Test-FileExists -FilePath 'C:\Data\myfile.txt'
```

Ключевые элементы:

- `function Name { ... }` — определение функции.
- `param(...)` — параметры функции.
- `Test-Path` — проверка пути.
- `-LiteralPath` — трактовать путь буквально.
- `-PathType Leaf` — ожидать файл, а не каталог.

### Функция сведений о пользователе AD

В видео с помощью Copilot создаётся `Get-UserInfo`. Рабочая версия:

```powershell
function Get-UserInfo {
    param(
        [Parameter(Mandatory)]
        [string]$Identity
    )

    Get-ADUser -Identity $Identity -Properties Department |
        Select-Object Name, SamAccountName, Department, Enabled
}

Get-UserInfo -Identity 'Administrator'
```

Функции, введённые непосредственно в консоль, существуют только до завершения сессии. Для повторного использования сохраните их в `.ps1`, модуле или профиле.

## 14. Managing execution policies

### Проверить текущие политики

```powershell
Get-ExecutionPolicy
Get-ExecutionPolicy -List
```

### Команда, показанная в курсе

```powershell
Set-ExecutionPolicy -ExecutionPolicy Unrestricted
```

По умолчанию применяется scope `LocalMachine`, поэтому нужны права администратора.

### Более безопасный типичный вариант

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Для среды, где все сценарии подписываются:

```powershell
Set-ExecutionPolicy -ExecutionPolicy AllSigned -Scope LocalMachine
```

Разблокировать один проверенный скачанный файл, не ослабляя общую политику:

```powershell
Unblock-File -Path '.\script.ps1'
```

### Получить справку

```powershell
Get-Help Set-ExecutionPolicy -Full
```

### Удалённо проверить и изменить политику

```powershell
Invoke-Command -ComputerName 'DC02' -ScriptBlock {
    Get-ExecutionPolicy -List
}
```

Если изменение действительно необходимо:

```powershell
Invoke-Command -ComputerName 'DC02' -ScriptBlock {
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope LocalMachine -Force
    Get-ExecutionPolicy -List
}
```

> Execution policy — защита от случайного запуска неподходящих сценариев, а не полноценная граница безопасности. Group Policy имеет приоритет над локальными scopes.

## 21. Logging PowerShell cmdlets

### Виды журналирования из урока

- **Script Block Logging** — содержимое команд, функций и script blocks.
- **Module Logging** — выполнение команд выбранных модулей.
- **Transcription** — ввод и консольный вывод сессии.
- **Engine Logging** — внутренние события запуска и остановки PowerShell.
- **Protected Event Logging** — CMS-шифрование чувствительного содержимого событий.

### Script Block Logging для PowerShell 7 — скрипт из кадра

```powershell
function Enable-PSScriptBlockLogging {
    $basePath = @(
        'HKLM:\Software\Policies\Microsoft'
        'PowerShellCore\ScriptBlockLogging'
    ) -join '\'

    if (-not (Test-Path $basePath)) {
        $null = New-Item $basePath -Force
    }

    Set-ItemProperty $basePath `
        -Name EnableScriptBlockLogging `
        -Value '1'
}

Enable-PSScriptBlockLogging
```

### Windows PowerShell 5.1 — другой раздел реестра

```powershell
$basePath = 'HKLM:\Software\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging'

if (-not (Test-Path $basePath)) {
    $null = New-Item -Path $basePath -Force
}

Set-ItemProperty -Path $basePath `
    -Name EnableScriptBlockLogging `
    -Type DWord `
    -Value 1
```

В домене предпочтительно включать настройку централизованно через Group Policy.

### Прочитать события Script Block Logging

Windows PowerShell 5.1:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-PowerShell/Operational'
    Id      = 4104
} -MaxEvents 100 |
    Select-Object TimeCreated, Id, UserId, Message
```

PowerShell 7:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'PowerShellCore/Operational'
    Id      = 4104
} -MaxEvents 100 |
    Select-Object TimeCreated, Id, UserId, Message
```

### Ручная транскрипция сессии

```powershell
$directory = 'C:\ProgramData\PowerShell\Transcripts'
New-Item -ItemType Directory -Path $directory -Force | Out-Null

Start-Transcript `
    -OutputDirectory $directory `
    -IncludeInvocationHeader

# Административные команды

Stop-Transcript
```

Транскрипты и Script Block Logging могут записывать чувствительные значения. Ограничьте ACL, настройте централизованный сбор, размер журналов, retention и при необходимости Protected Event Logging.

## 23. CIM demonstration

### Сведения о локальных дисках

```powershell

```

## B. Инвентаризация нескольких серверов через CIM

```powershell
[CmdletBinding()]
param(
    [Parameter(Mandatory)]
    [string[]]$ComputerName
)

$sessions = New-CimSession -ComputerName $ComputerName

try {
    foreach ($session in $sessions) {
        $os = Get-CimInstance `
            -CimSession $session `
            -ClassName Win32_OperatingSystem

        $memory = Get-CimInstance `
            -CimSession $session `
            -ClassName Win32_PhysicalMemory |
            Measure-Object Capacity -Sum

        [pscustomobject]@{
            ComputerName = $session.ComputerName
            OS           = $os.Caption
            Version      = $os.Version
            MemoryGB     = [math]::Round($memory.Sum / 1GB, 2)
            LastBoot     = $os.LastBootUpTime
        }
    }
}
finally {
    $sessions | Remove-CimSession
}
```

# Важные поправки для рабочей среды

## 1. `Unrestricted` — только учебный пример

Курс демонстрирует `Set-ExecutionPolicy Unrestricted` и даже добавляет его в профиль. Для рабочей среды это слишком широкая настройка. Обычно выбирают `RemoteSigned`, `AllSigned` или управляют политикой через Group Policy. Для одного проверенного файла можно использовать `Unblock-File`.

## 2. `Get-WmiObject Win32_Product` нежелателен

Команда из курса может быть медленной и инициировать consistency check/repair MSI-пакетов. Для инвентаризации лучше читать uninstall-разделы Registry или использовать корпоративный inventory-инструмент.

## 3. `Get-EventLog` — совместимость, `Get-WinEvent` — современный вариант

`Get-EventLog` работает только с classic logs и сохранён для обратной совместимости. `Get-WinEvent` поддерживает современные Windows Event Log/ETW-журналы и эффективные фильтры через `-FilterHashtable`.

## 4. PowerShell 7 и Windows PowerShell 5.1 — разные продукты

Они работают параллельно. Не все старые Windows-модули одинаково совместимы с PowerShell 7. Проверяйте `$PSVersionTable`, `Get-Module -ListAvailable` и совместимость конкретного модуля.

## 5. Не очищайте журналы без причины

`Clear-EventLog` уничтожает текущие события выбранного classic log. Перед очисткой экспортируйте журнал, если он может понадобиться для аудита, диагностики или расследования.

## 6. Логирование способно записать секреты

Script Block Logging и transcription могут зафиксировать токены, пароли, connection strings и другие чувствительные данные, если они попали в командную строку или вывод. Защищайте ACL, централизованный сбор и ключи Protected Event Logging.
