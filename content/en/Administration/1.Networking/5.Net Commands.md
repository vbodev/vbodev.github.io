## 1. `ping` (Packet Internet Groper)

**Essence:** This is a «sonar» for networks. Uses the **ICMP** (Internet Control Message Protocol) protocol. The computer sends an «Echo Request» and waits for an «Echo Reply».

**What it exactly tells us:**
1. **Availability:** Whether the remote node is alive.
2. **Packet Loss:** If you sent 4 packets but only 3 returned (25% loss), the line is noisy, overloaded, or equipment is failing. For VoIP or gaming, this is critical.
3. **Response time (Latency/RTT):** How many milliseconds the signal traveled round-trip.
    - < 1 ms: Device in your local network.
    - 10-50 ms: Good internet (within the country/region).
    - > 150 ms: Another continent or satellite channel.
**Useful switches (CMD):**
- `ping -t` — **Infinite ping.** Indispensable when configuring antennas or plugging/unplugging cables.
- `ping -l 1000` — **Packet size.** By default, packets are small (32 bytes). The `-l` (length) switch allows sending a «heavy» packet (e.g., 1000 or 1500 bytes) to check whether the network can handle the load (MTU).
- `ping -a` — Tries to find the computer name from an IP address.

## 2. `tracert` (Trace Route)

**Essence:** Shows the route map.
**How it works (TTL Magic):** Every IP packet has a **TTL (Time To Live)** field — «lifetime». This is a hop counter.
1. The command sends a packet with TTL=1. It reaches the first router, TTL becomes 0, the router kills the packet and sends you a «Time exceeded» message. This is how we learn the IP of the first router.
2. A packet with TTL=2 is sent. It passes the first router, dies at the second. We learn the IP of the second.
3. And so on until we reach the target.

**Diagnostic nuances:**
- **Where does the internet slow down?** If in the first steps (within the provider's network) the response time is small (1-5 ms), but when transitioning to the backbone provider (e.g., Telia or Level3) it jumps to 200 ms — it's not your router that's to blame, but global channels.
- **Switch `-d`:** `tracert -d ya.ru`. The most useful option! It prevents the command from converting IP addresses to node names. This speeds up tracing significantly.

## 3. `ipconfig` (Internet Protocol Configuration)

**Essence:** The passport of your network adapter.
**Detailed breakdown of parameters:**
- **Subnet Mask:** Determines the boundaries of your local network (who is «in» and who is «out»). Usually `255.255.255.0`.
- **Default Gateway:** This is the IP address of your router. This is where the computer sends all packets destined for the internet. If the gateway doesn't respond to ping — the problem is in your Wi-Fi or the cable to the router.
**Resuscitation commands (if the network is «frozen» or IP wasn't assigned):**
1. `ipconfig /release` — Release the current IP address.
2. `ipconfig /renew` — Request a new IP address from the DHCP server (router).
3. `ipconfig /flushdns` — **Clear DNS cache.** Very important! If a website moved to a new server, but your computer remembered the old address, this command will force it to «forget» the old one and ask again.

## 4. `nslookup` (Name Server Lookup)

**Essence:** Direct communication with a DNS server. This is a tool for talking to the internet's phone book.
**Operating modes:**
1. **Simple:** `nslookup google.com` — uses your default DNS.
2. **Checking alternative:** `nslookup google.com 1.1.1.1` — asks the address from Cloudflare's server (1.1.1.1), ignoring your provider's settings. If this works but without `1.1.1.1` it doesn't — your provider's DNS is broken.
**Advanced level (Record types):**
- Run just `nslookup` (press Enter).
- Inside, type `set type=mx`.
- Type `gmail.com`.
- You'll see Google's mail servers. This is needed to understand where the domain's email goes.

## 5. `netstat` (Network Statistics)

**Essence:** X-ray of active connections. Shows who is connected where and via which port.
**Important states:**
- **ESTABLISHED:** Stable connection, data transfer is running.
- **LISTENING:** A program opened a port and is waiting for connections. This is a potential security hole.
- **TIME_WAIT:** Connection closed, but system waits to ensure all packets arrived.
**Best key combination:** `netstat -ano`
- `-a`: All ports.
- `-n`: Numeric view (shows IPs instead of names, works faster).
- `-o`: Adds the **PID (Process ID)** column.
**How to catch a virus/spy:**
1. Run `netstat -ano`.
2. See a strange connection to a foreign IP.
3. Note its PID (e.g., 4520).
4. Open Task Manager → Details → Find PID 4520.
5. See the process name doing it.

## All Commands

|**Command**|**Parameters (Switches)**|**Usage Example**|**Why (Situation)**|
|---|---|---|---|
|**PING**|`-t`|`ping google.com -t`|**Infinite ping.** Indispensable when plugging cables or rebooting the router and waiting for «internet to appear». (Stop: `Ctrl+C`)|
||`-l` (size)|`ping ya.ru -l 1400`|**Stability check.** Sends a heavy packet (1400 bytes). If a normal ping works but this one is lost — problem with line quality or MTU settings.|
|**IPCONFIG**|`/all`|`ipconfig /all`|**Full dossier.** Shows MAC address and DNS servers (regular `ipconfig` hides this).|
||`/flushdns`|`ipconfig /flushdns`|**«Pill» for glitches.** Clears DNS cache. If a site changed its IP and you see the old version or an error — type this.|
||`/renew`|`ipconfig /renew`|**IP request.** Forces the router to issue a new address. Helps if there are IP address conflicts.|
|**TRACERT**|`-d`|`tracert -d 8.8.8.8`|**Fast trace.** Doesn't waste time looking up node names, shows only IPs. Works 3-5x faster.|
|**NETSTAT**|`-ano`|`netstat -ano`|**Full scan.** `-a`: all ports, `-n`: as numbers (fast), `-o`: shows process **PID**. By PID in Task Manager you can find the program using the network.|
||`-ab`|`netstat -ab`|**Finding the culprit.** Shows the **name** of the program (exe) that opened the port. _Requires running command prompt as Administrator._|
|**NSLOOKUP**|(server IP)|`nslookup ya.ru 8.8.8.8`|**Checking «from the outside».** Asks the website's IP not from your provider, but specifically from the Google server (8.8.8.8). Helps understand who's to blame: the provider or the site.|
