## 21. Logging PowerShell cmdlets

### Logging types from the lesson

- **Script Block Logging** — contents of commands, functions, and script blocks.
- **Module Logging** — command execution in selected modules.
- **Transcription** — session input and console output.
- **Engine Logging** — internal PowerShell startup and shutdown events.
- **Protected Event Logging** — CMS encryption for sensitive event contents.

### Script Block Logging for PowerShell 7 — script from the screen

```powershell
function Enable-PSScriptBlockLogging {
    $basePath = @(
        'HKLM:\Software\Policies\Microsoft'
        'PowerShellCore\ScriptBlockLogging'
    ) -join '\'

    if (-not (Test-Path $basePath)) {
        $null = New-Item $basePath -Force
    }

    Set-ItemProperty $basePath `
        -Name EnableScriptBlockLogging `
        -Value '1'
}

Enable-PSScriptBlockLogging
```

### Windows PowerShell 5.1 — a different registry location

```powershell
$basePath = 'HKLM:\Software\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging'

if (-not (Test-Path $basePath)) {
    $null = New-Item -Path $basePath -Force
}

Set-ItemProperty -Path $basePath `
    -Name EnableScriptBlockLogging `
    -Type DWord `
    -Value 1
```

In a domain, enable this setting centrally through Group Policy where possible.

### Read Script Block Logging events

Windows PowerShell 5.1:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-PowerShell/Operational'
    Id      = 4104
} -MaxEvents 100 |
    Select-Object TimeCreated, Id, UserId, Message
```

PowerShell 7:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'PowerShellCore/Operational'
    Id      = 4104
} -MaxEvents 100 |
    Select-Object TimeCreated, Id, UserId, Message
```

### Manually transcribe a session

```powershell
$directory = 'C:\ProgramData\PowerShell\Transcripts'
New-Item -ItemType Directory -Path $directory -Force | Out-Null

Start-Transcript `
    -OutputDirectory $directory `
    -IncludeInvocationHeader

# Administrative commands

Stop-Transcript
```

Transcripts and Script Block Logging can record sensitive values. Restrict ACLs, configure centralized collection, log size and retention, and use Protected Event Logging where necessary.

## 23. CIM demonstration

### Local disk information

```powershell
Get-CimInstance -ClassName Win32_DiskDrive |
    Select-Object Model, Size, Status
```

A more convenient size representation:

```powershell
Get-CimInstance -ClassName Win32_DiskDrive |
    Select-Object Model,
        @{Name = 'SizeGB'; Expression = { [math]::Round($_.Size / 1GB, 2) }},
        Status
```

### Create a remote CIM session

```powershell
$session = New-CimSession -ComputerName 'PS-SERVER01'
```

### Determine total physical memory

```powershell
$memory = Get-CimInstance `
    -CimSession $session `
    -ClassName Win32_PhysicalMemory |
    Measure-Object -Property Capacity -Sum

[pscustomobject]@{
    ComputerName = 'PS-SERVER01'
    MemoryGB     = [math]::Round($memory.Sum / 1GB, 3)
}
```

### Close the session

```powershell
Remove-CimSession -CimSession $session
```

# Ready-to-use scripts

## A. `serverinfo.ps1` — consolidated practical course script

```powershell
[CmdletBinding()]
param(
    [string]$OutputDirectory = 'C:\Data'
)

New-Item -ItemType Directory -Path $OutputDirectory -Force |
    Out-Null

Get-ComputerInfo |
    Out-File -FilePath (Join-Path $OutputDirectory 'computer-info.txt') `
        -Encoding utf8

Get-Service |
    Where-Object Status -eq 'Running' |
    Sort-Object DisplayName |
    Out-File -FilePath (Join-Path $OutputDirectory 'running-services.txt') `
        -Encoding utf8

Get-Process |
    Sort-Object CPU -Descending |
    Select-Object Name, Id, CPU, WorkingSet |
    Out-File -FilePath (Join-Path $OutputDirectory 'processes.txt') `
        -Encoding utf8

"Reports saved to $OutputDirectory"
```

Run:

```powershell
.\serverinfo.ps1
.\serverinfo.ps1 -OutputDirectory 'D:\Reports'
```

## B. Inventory multiple servers through CIM

```powershell
[CmdletBinding()]
param(
    [Parameter(Mandatory)]
    [string[]]$ComputerName
)

$sessions = New-CimSession -ComputerName $ComputerName

try {
    foreach ($session in $sessions) {
        $os = Get-CimInstance `
            -CimSession $session `
            -ClassName Win32_OperatingSystem

        $memory = Get-CimInstance `
            -CimSession $session `
            -ClassName Win32_PhysicalMemory |
            Measure-Object Capacity -Sum

        [pscustomobject]@{
            ComputerName = $session.ComputerName
            OS           = $os.Caption
            Version      = $os.Version
            MemoryGB     = [math]::Round($memory.Sum / 1GB, 2)
            LastBoot     = $os.LastBootUpTime
        }
    }
}
finally {
    $sessions | Remove-CimSession
}
```

## C. Check PowerShell Script Block Logging

```powershell
[CmdletBinding()]
param(
    [ValidateSet('WindowsPowerShell', 'PowerShell7')]
    [string]$Edition = 'WindowsPowerShell',

    [int]$Hours = 24
)

$logName = if ($Edition -eq 'PowerShell7') {
    'PowerShellCore/Operational'
}
else {
    'Microsoft-Windows-PowerShell/Operational'
}

Get-WinEvent -FilterHashtable @{
    LogName   = $logName
    Id        = 4104
    StartTime = (Get-Date).AddHours(-$Hours)

```

## D. Safely inventory installed applications

```powershell
[CmdletBinding()]
param(
    [string]$OutputPath = 'C:\Data\applications.csv'
)

$parent = Split-Path -Parent $OutputPath
New-Item -ItemType Directory -Path $parent -Force | Out-Null

$paths = @(
    'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*'
    'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*'
)

Get-ItemProperty -Path $paths |
    Where-Object DisplayName |
    Select-Object `
        @{Name = 'Name'; Expression = { $_.DisplayName }},
        @{Name = 'Version'; Expression = { $_.DisplayVersion }},
        Publisher,
        InstallDate |
    Sort-Object Name -Unique |
    Export-Csv -Path $OutputPath -NoTypeInformation -Encoding utf8
```

# Important production-environment considerations

## 1. `Unrestricted` is only a learning example

The course demonstrates `Set-ExecutionPolicy Unrestricted` and even adds it to a profile. That setting is too broad for a production environment. Normally use `RemoteSigned`, `AllSigned`, or manage the policy with Group Policy. Use `Unblock-File` for a single verified file.

## 2. `Get-WmiObject Win32_Product` is not advisable

The command from the course can be slow and can initiate consistency checks or repairs of MSI packages. For inventory, read the Registry uninstall keys or use an enterprise inventory tool.

## 3. `Get-EventLog` is for compatibility; `Get-WinEvent` is the modern option

`Get-EventLog` works only with classic logs and is retained for backward compatibility. `Get-WinEvent` supports modern Windows Event Log/ETW logs and efficient filters through `-FilterHashtable`.

## 4. PowerShell 7 and Windows PowerShell 5.1 are separate products

They run side by side. Not every legacy Windows module is equally compatible with PowerShell 7. Check `$PSVersionTable`, `Get-Module -ListAvailable`, and the compatibility of the specific module.

## 5. Do not clear logs without a reason

`Clear-EventLog` destroys the current events in the selected classic log. Export the log before clearing it if it may be required for audit, diagnostics, or an investigation.

## 6. Logging can record secrets

Script Block Logging and transcription can capture tokens, passwords, connection strings, and other sensitive data if they reach the command line or output. Protect ACLs, centralized collection, and Protected Event Logging keys.

## 7. PowerShell cmdlet syntax

### Basic form

```text
Verb-Noun -Parameter Value
```

Examples:

```powershell
Get-Disk
Get-Disk -Number 0
```

Not every displayed property is a parameter. For example, `HealthStatus` appears in the output of `Get-Disk`, but that does not mean that a `-HealthStatus` parameter exists.

Correctly filter by the property:

```powershell
Get-Disk | Where-Object HealthStatus -eq 'Healthy'
```

### Variables

```powershell
$MyVariable = 'I Love Pizza'
$MyVariable
```

A practical Active Directory example:

```powershell
$admin = 'Administrator'
Get-ADUser $admin
```

### Run a script from the current directory

```powershell
.\script.ps1
```

In Windows, `./script.ps1` is conventionally written as `.\script.ps1`.

### The `dir` alias

In PowerShell, `dir` refers to `Get-ChildItem`:

```powershell
Get-Alias dir
Get-ChildItem
```

Legacy CMD switches do not necessarily work with an alias. For example, `dir *.txt /s` is CMD syntax. The PowerShell equivalent is:

```powershell
Get-ChildItem -Path . -Filter '*.txt' -Recurse
```

## 12. Creating functions

### Function to test whether a file exists

The video shows a `Test-FileExists` function. This is a working reconstructed version:

```powershell
function Test-FileExists {
    param(
        [Parameter(Mandatory)]
        [string]$FilePath
    )

    if (Test-Path -LiteralPath $FilePath -PathType Leaf) {
        "File exists: $FilePath"
    }
    else {
        "File does not exist: $FilePath"
    }
}

Test-FileExists -FilePath 'C:\Data\myfile.txt'
```

Key elements:

- `function Name { ... }` — function definition.
- `param(...)` — function parameters.
- `Test-Path` — tests a path.
- `-LiteralPath` — treats the path literally.
- `-PathType Leaf` — expects a file rather than a directory.

### Function for AD user information

The video uses Copilot to create `Get-UserInfo`. This is a working version:

```powershell
function Get-UserInfo {
    param(
        [Parameter(Mandatory)]
        [string]$Identity
    )

    Get-ADUser -Identity $Identity -Properties Department |
        Select-Object Name, SamAccountName, Department, Enabled
}

Get-UserInfo -Identity 'Administrator'
```

Functions entered directly in the console exist only until the session ends. To reuse them, save them in a `.ps1` file, module, or profile.

## 14. Managing execution policies

### Check current policies

```powershell
Get-ExecutionPolicy
Get-ExecutionPolicy -List
```

### Command shown in the course

```powershell
Set-ExecutionPolicy -ExecutionPolicy Unrestricted
```

By default, this applies at the `LocalMachine` scope, so administrator rights are required.

### A safer common option

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

For an environment where every script is signed:

```powershell
Set-ExecutionPolicy -ExecutionPolicy AllSigned -Scope LocalMachine
```

To unblock one verified downloaded file without weakening the overall policy:

```powershell
Unblock-File -Path '.\script.ps1'
```

### Get help

```powershell
Get-Help Set-ExecutionPolicy -Full
```

### Check and change a policy remotely

```powershell
Invoke-Command -ComputerName 'DC02' -ScriptBlock {
    Get-ExecutionPolicy -List
}
```

If a change is genuinely required:

```powershell
Invoke-Command -ComputerName 'DC02' -ScriptBlock {
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope LocalMachine -Force
    Get-ExecutionPolicy -List
}
```

> Execution policy protects against inadvertently running unsuitable scripts; it is not a complete security boundary. Group Policy takes precedence over local scopes.
