## 1. Primitive and Reference Types

#### **Primitive Types**
These are basic data types that store the **value directly**, rather than a reference to an object.
Java has **8 primitive types**:

| Category  | Type  | Size  | Range  | Example Value  |
| ------------ | --------- | ------------------------- | ------------------- | --------------------- |
| Integers  | `byte`  | 1 byte  | -128 … 127  | `byte b = 10;`  |
|  | `short`  | 2 bytes  | -32,768 … 32,767  | `short s = 500;`  |
|  | `int`  | 4 bytes  | ≈ ±2 billion  | `int i = 1000;`  |
|  | `long`  | 8 bytes  | ±9 quintillions  | `long l = 100000L;`  |
| Floating-point | `float`  | 4 bytes  | ~7 decimal places  | `float f = 1.23f;`  |
|  | `double`  | 8 bytes  | ~15 decimal places | `double d = 1.23456;` |
| Character  | `char`  | 2 bytes  | Unicode characters  | `char c = 'A';`  |
| Logical  | `boolean` | 1 bit (1 byte in memory) | `true` / `false`  | `boolean b = true;`  |
💡 **Features:**
- Primitives cannot be `null`.
- By default, they are initialized to zero (0, 0.0, `false`, `'\u0000'`) if they are class fields.
- In local variables, you **must** explicitly assign a value – otherwise, a compilation error will occur.
#### **Reference Types**
Reference types **do not store the value**, but **contain the memory address** of the object (in the heap).

Examples:
```java
String s = "Hello";
int[] numbers = {1, 2, 3};
Person p = new Person("Alex");
```

Here:
- `s` holds a reference to a `String` object in the heap.
- `numbers` is a reference to an array.
- `p` is a reference to a `Person` object.
💡 **All classes, arrays, and interfaces** are reference types.
Even `String` is not a primitive, although it behaves as such due to its _immutability_ (unchangeability).
## 2. Autoboxing and Unboxing

To use primitives as objects, Java provides **wrapper classes**:

| Primitive  | Wrapper Class |
| --------- | ------------- |
| `int`  | `Integer`  |
| `double`  | `Double`  |
| `boolean` | `Boolean`  |
| `char`  | `Character`  |
| `long`  | `Long`  |
| `float`  | `Float`  |
| `short`  | `Short`  |
| `byte`  | `Byte`  |

**Autoboxing** is the automatic conversion of a primitive to an object:
```java
Integer num = 5; // automatic conversion int → Integer
```

**Unboxing** is the reverse conversion:
```java
int x = num; // automatic extraction Integer → int
```

💡 **Caveats:**
```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b); // true (IntegerCache from -128 to 127)

Integer c = 128;
Integer d = 128;
System.out.println(c == d); // false (different objects created)
```
→ To compare wrappers, use `.equals()`, not `==`.
## 3. Memory: Stack vs Heap

#### **Stack**
- Stores **method calls and local variables**.
- Each thread has its **own stack**.
- Data disappears when exiting a method.

Example:
```java
void example() {
  int x = 10;  // stored on the stack
  String s = "Hello";  // reference stored on the stack, object in heap
}
```
#### **Heap**
- Stores **objects** (all class instances, arrays, strings).
- Shared for all threads.
- Managed by the **Garbage Collector** (GC).

Example:
```java
Person p = new Person("Alex"); // object in heap, reference in stack
```
## 4. Object Lifecycle

1. **Creation**: `new` allocates memory in the heap.
2. **Usage**: The object lives as long as there is at least one reference to it.
3. **Garbage Collection**: When there are no references to an object, the GC cleans it up.

GC is not called manually, but you can **request**:
```java
System.gc(); // only a recommendation, not a guarantee
```
## 5. Method Parameter Passing

Java **always passes arguments by value**.
But if it's a reference type, the **reference itself is copied**, not the object.

```java
void modify(Person p) {
  p.name = "Changed"; // will change the original object
}
```

📍 This means:
- For primitives, the value is copied, the original remains unchanged;
- For objects, the reference is copied, and you can modify the internal fields.
## 6. JVM Memory Concepts

| Memory Area | Purpose |
|---|---|
| **Stack** | Local variables and method calls |
| **Heap** | All objects managed by GC |
| **Metaspace (before Java 8 — PermGen)** | Stores class metadata and bytecode |
| **PC Register** | Stores the current instruction of the thread |
| **Native Method Stack** | Stack for calls to native (non-Java) methods |
## 7. Best Practices

- ✅ Use primitives instead of wrappers if `null` is not required.
- ✅ Avoid overuse of autoboxing within loops – it creates unnecessary objects.
- ✅ Always use `.equals()` to compare wrappers.
- ✅ Remember that `String` is immutable (creates new objects when modified).
- ✅ Optimize memory using `StringBuilder` if you are performing concatenation within a loop.
